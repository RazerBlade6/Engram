# Decisions

Each decision with its reasoning, numbered in the order it was made. The other documents cite them as D1, D2 and so on. A later decision that changes an earlier one says so; the earlier row stays as it was.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Rationale                                                                                                                                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Built around active recall and spaced repetition; chat is secondary                                                                                                                                                                                                                                                                                                                                                                                                                   | Strongest evidence base for learning outcomes; "chat with a PDF" is a crowded category                                                                                                                                               |
| 2   | Generated cards strictly grounded; chat falls back to labeled general knowledge                                                                                                                                                                                                                                                                                                                                                                                                       | Cards are memorized, so they must be right. Chat should still help when the material explains something badly.                                                                                                                       |
| 3   | Cards auto-accepted, flagged in review, optional triage                                                                                                                                                                                                                                                                                                                                                                                                                               | A mandatory triage step adds friction; flags still produce eval labels                                                                                                                                                               |
| 4   | Card generation triggered per chapter by "mark covered"                                                                                                                                                                                                                                                                                                                                                                                                                               | Cost scales with use, the deck follows the syllabus, a single obvious action                                                                                                                                                         |
| 5   | Desktop-first, keyboard-driven review                                                                                                                                                                                                                                                                                                                                                                                                                                                 | The primary context is studying at a desk on a laptop                                                                                                                                                                                |
| 6   | No gamification, no reminders or notifications                                                                                                                                                                                                                                                                                                                                                                                                                                        | The tool should be available, not pushy; users firmly declined reminders in testing                                                                                                                                                  |
| 7   | Provider-agnostic LLM layer, routing decided by benchmark                                                                                                                                                                                                                                                                                                                                                                                                                             | Best quality per cost for each job, and a measurable model choice                                                                                                                                                                    |
| 8   | Docling plus vision captions, section-aware chunks with bounding boxes                                                                                                                                                                                                                                                                                                                                                                                                                | Diagram-heavy, multi-column textbooks need layout-aware parsing; precise citations build trust                                                                                                                                       |
| 9   | Own retrieval pipeline instead of LlamaIndex                                                                                                                                                                                                                                                                                                                                                                                                                                          | Tunable, measurable, no framework lock-in                                                                                                                                                                                            |
| 10  | Supabase + Vercel, Postgres-backed job queue (backend hosting in D35)                                                                                                                                                                                                                                                                                                                                                                                                                 | Long-running ingestion needs a worker; one database covers relational, vector and full-text data at low cost                                                                                                                         |
| 11  | Invite-only accounts plus a public read-only demo                                                                                                                                                                                                                                                                                                                                                                                                                                     | Bounded costs; anyone can evaluate the product without uploading anything                                                                                                                                                            |
| 12  | OpenStax for demo and eval corpus; user uploads never used                                                                                                                                                                                                                                                                                                                                                                                                                            | Openly licensed and legally shareable; user data stays private                                                                                                                                                                       |
| 13  | Dedicated UI/UX phase before daily use                                                                                                                                                                                                                                                                                                                                                                                                                                                | A bad first impression is hard to undo, and friction is the main risk                                                                                                                                                                |
| 14  | Mockups validated with users before writing code                                                                                                                                                                                                                                                                                                                                                                                                                                      | Changing a mockup is far cheaper than changing a built app                                                                                                                                                                           |
| 15  | Anki export                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | No lock-in lowers the cost of trying Engram                                                                                                                                                                                          |
| 16  | Four self-ratings: Forgot, Hard, Got it, Easy                                                                                                                                                                                                                                                                                                                                                                                                                                         | Understood in testing, and preferred over two buttons                                                                                                                                                                                |
| 17  | Calendar of exams, quizzes and deadlines per course; no lecture timetable                                                                                                                                                                                                                                                                                                                                                                                                             | Requested in testing; a timetable is a lot of entry work for information students already know                                                                                                                                       |
| 18  | Dates via quick-add, then syllabus extraction; next dates shown on Today                                                                                                                                                                                                                                                                                                                                                                                                              | Low-effort entry; the exam date on Today was the first thing noticed in testing                                                                                                                                                      |
| 19  | Calendar in Phase 1, exam focus mode stays in Phase 3; no calendar feed unless asked for                                                                                                                                                                                                                                                                                                                                                                                              | Cheap to build and a reason to open the app beyond reviews; a feed is close to the declined reminders                                                                                                                                |
| 20  | Review order (mixed, blocked, separate) chosen by a Phase 2 experiment, set by admin only                                                                                                                                                                                                                                                                                                                                                                                             | Users wanted clearer separation of card types; the zero-configuration rule keeps it out of settings                                                                                                                                  |
| 21  | One-time welcome screen; first meaningful action within 5 s on a fresh account                                                                                                                                                                                                                                                                                                                                                                                                        | The first load was the most disorienting moment in testing                                                                                                                                                                           |
| 22  | File upload and link entry as separate controls                                                                                                                                                                                                                                                                                                                                                                                                                                       | The link field was mistaken for the upload area in testing                                                                                                                                                                           |
| 23  | Light theme by default with large, high-contrast reading text; dark theme later                                                                                                                                                                                                                                                                                                                                                                                                       | Light preferred for long reading sessions; dark offered as an option once the light theme is settled                                                                                                                                 |
| 24  | Row-level security is the single enforcement point for data access                                                                                                                                                                                                                                                                                                                                                                                                                    | The API runs each request as the signed-in user, so one set of policies, tested in CI, guards every path                                                                                                                             |
| 25  | Provisional per-job model defaults in config until the eval suites exist                                                                                                                                                                                                                                                                                                                                                                                                              | Routing by benchmark needs the benchmark; defaults keep Phase 1 moving and stay swappable                                                                                                                                            |
| 26  | Card generation starts on the stronger model                                                                                                                                                                                                                                                                                                                                                                                                                                          | Cards are memorized; a cheaper model must pass the card-quality eval first                                                                                                                                                           |
| 27  | Citations returned as chunk IDs through the provider interface                                                                                                                                                                                                                                                                                                                                                                                                                        | Keeps native Citations without tying the product to one provider                                                                                                                                                                     |
| 28  | Only paid LLM tiers that exclude training on submitted content                                                                                                                                                                                                                                                                                                                                                                                                                        | Uploaded materials are copyrighted and private                                                                                                                                                                                       |
| 29  | Unmarking a chapter keeps its cards and stops generation that hasn't finished                                                                                                                                                                                                                                                                                                                                                                                                         | Unmarking is usually a slip or a change of plan; review history shouldn't be lost to it                                                                                                                                              |
| 30  | Each card quotes its source verbatim; cards whose quotes aren't found are dropped                                                                                                                                                                                                                                                                                                                                                                                                     | Grounding is checked in code, not trusted to the prompt (D2)                                                                                                                                                                         |
| 31  | About one card per 150 words of chapter, end-of-chapter questions skipped                                                                                                                                                                                                                                                                                                                                                                                                             | Uncapped, a 30-page chapter gave 150 cards, many trivia: more than a student keeps up with                                                                                                                                           |
| 32  | Up to 20 new cards a day, chapters covered first                                                                                                                                                                                                                                                                                                                                                                                                                                      | Bounds the daily load at roughly 15 minutes once reviews build up                                                                                                                                                                    |
| 33  | Only each card's current schedule is stored; review history waits for consent                                                                                                                                                                                                                                                                                                                                                                                                         | Scheduling needs no history, and ratings are usage events                                                                                                                                                                            |
| 34  | Multiple choice grades itself: right is "Got it", wrong is "Forgot"                                                                                                                                                                                                                                                                                                                                                                                                                   | One action per card; asking how well you knew an answer you just got wrong adds a step                                                                                                                                               |
| 35  | API on Cloud Run, worker on Modal, both scaling to zero                                                                                                                                                                                                                                                                                                                                                                                                                               | The backend is idle almost all the time; free tiers cover a few users, at a few seconds on the first load after a quiet spell                                                                                                        |
| 36  | Review order is set per person, and every order shows the same day's cards                                                                                                                                                                                                                                                                                                                                                                                                            | Each user can try each order in turn, and only the arrangement differs between them                                                                                                                                                  |
| 37  | Chat retrieves 8 passages by hybrid search (vectors and keywords, fused by rank), Opus at low effort                                                                                                                                                                                                                                                                                                                                                                                  | First words in about 1.5 seconds, about $0.035 a question; keywords catch names that embeddings blur                                                                                                                                 |
| 38  | Chat conversations aren't stored on the server; they last as long as the browser tab                                                                                                                                                                                                                                                                                                                                                                                                  | Questions can be personal, and nothing needs them later; only token counts are recorded, with no user                                                                                                                                |
| 39  | An answer outside the materials is detected by a marker the model writes, not by missing citations                                                                                                                                                                                                                                                                                                                                                                                    | An off-topic answer can still cite a passing mention, which would hide the "not from your materials" label                                                                                                                           |
| 40  | Dates are calendar days with no time; "upcoming" is worked out in the browser                                                                                                                                                                                                                                                                                                                                                                                                         | Students know the time of their exam; a day with no time zone can't shift when the server's today differs from theirs                                                                                                                |
| 41  | A date's chapters are recorded from Phase 1, though nothing uses them until focus mode                                                                                                                                                                                                                                                                                                                                                                                                | Dates entered from the start already say what they cover, so focus mode works on them without re-entry                                                                                                                               |
| 42  | Consent to usage logging is recorded by an admin, per person; turning it off stops logging, and past events are deleted on request                                                                                                                                                                                                                                                                                                                                                    | Users have no settings (zero configuration), and consent is asked for in person                                                                                                                                                      |
| 43  | Events never contain text: no questions, answers, card content or date names                                                                                                                                                                                                                                                                                                                                                                                                          | The statistics need counts and timings, not words; nothing personal can leak from the log                                                                                                                                            |
| 44  | Each rating logs the scheduler state before and after, and the time since the last review                                                                                                                                                                                                                                                                                                                                                                                             | Enough to evaluate FSRS on real reviews, and later fit its parameters to each user                                                                                                                                                   |
| 45  | A new job wakes the worker through a database trigger; a sweep every 15 minutes catches retries                                                                                                                                                                                                                                                                                                                                                                                       | Every way a job is queued is covered in one place, and the worker costs nothing while idle                                                                                                                                           |
| 46  | Production deploys from `main` on push: migrations, then API and worker; Vercel deploys the web app itself                                                                                                                                                                                                                                                                                                                                                                            | The schema is never behind the code, and a deploy is just a fast-forward of `main`                                                                                                                                                   |
| 47  | CI and deploys run only for the parts of the repository a push changed                                                                                                                                                                                                                                                                                                                                                                                                                | A one-line web fix took about 8 minutes from push to live, almost all of it backend jobs it didn't touch                                                                                                                             |
| 48  | Students create their own courses; admins can create one for anyone; textbooks stay admin-only                                                                                                                                                                                                                                                                                                                                                                                        | A fresh account can start on its own; textbook ingestion is the costly step, so it stays with the operator                                                                                                                           |
| 49  | Files upload from the browser straight to Storage with a signed token; the API then checks and queues them                                                                                                                                                                                                                                                                                                                                                                            | Cloud Run caps request bodies at 32 MiB, well under a textbook                                                                                                                                                                       |
| 50  | A navigation bar on every signed-in page except review                                                                                                                                                                                                                                                                                                                                                                                                                                | Pages reachable only by typed address don't exist for users; review keeps the screen to the card                                                                                                                                     |
| 51  | A running job renews its lock every minute; a lock five minutes old means the worker is gone                                                                                                                                                                                                                                                                                                                                                                                          | Modal preempted a worker mid-ingestion, and the one-hour stale lock left the upload stuck as "processing"                                                                                                                            |
| 52  | The report control sits in the card's corner, with a keyboard shortcut, not under every card                                                                                                                                                                                                                                                                                                                                                                                          | Found at once in testing but rarely needed; under the card it competed with the ratings                                                                                                                                              |
| 53  | Waiting for cards shows how many have been made so far, with motion that respects reduced-motion settings                                                                                                                                                                                                                                                                                                                                                                             | The wait was clear but dull in testing; real progress says more than decoration                                                                                                                                                      |
| 54  | Dates are written out ("12 Nov 2026") and entered day/month/year in Engram's own date field                                                                                                                                                                                                                                                                                                                                                                                           | The browser's date input takes the order from the operating system, and mm/dd/yyyy confused a tester                                                                                                                                 |
| 55  | Blocked is the default review order; blocked and separate are compared in the first weeks of daily use (refines D20)                                                                                                                                                                                                                                                                                                                                                                  | A tester liked having the multiple choice at the end; the experiment needs daily use, which starts after Phase 2                                                                                                                     |
| 56  | Phase 2 is designed in the app on the local dev server, with sketches only where a design isn't working out (refines D14)                                                                                                                                                                                                                                                                                                                                                             | The flows already tested well, so this is polish; the exit session validates the result with a user                                                                                                                                  |
| 57  | The "Desk" look: what a student studies is drawn as a ruled index card on a grey desk, and the interface around it stays plain; Figtree for the interface, Literata only for text a student reads, and a handwritten face for the short note naming a card's course                                                                                                                                                                                                                   | Chosen from four directions. The index card explains the product at a glance; a serif interface felt too formal, but the serif reads well on cards and sources                                                                       |
| 58  | The four ratings are colored in four inks (plum, ochre, teal, blue), none of them red                                                                                                                                                                                                                                                                                                                                                                                                 | Color makes the choice faster, but a red "Forgot" reads as failing, against the no-guilt principle (D6)                                                                                                                              |
| 59  | No illustration; motion stays subtle except the card flip, which can be generous                                                                                                                                                                                                                                                                                                                                                                                                      | The card is what a student watches; anywhere else, motion would only distract                                                                                                                                                        |
| 60  | The welcome is a short tour of index cards, one per page, with back, next and skip; seen once per account                                                                                                                                                                                                                                                                                                                                                                             | A single welcome line explained Engram but not where things are; skip on every card and arrow keys keep it from standing between a student and their first review                                                                    |
| 61  | Removing a material cancels its jobs in the database; a running job stops within a minute, when its lock no longer renews                                                                                                                                                                                                                                                                                                                                                             | A removed textbook was read to the end, paying for every figure description                                                                                                                                                          |
| 62  | A section's heading is only matched within a page of its outline page; a chapter with no text fails card generation instead of making none                                                                                                                                                                                                                                                                                                                                            | Docling missed a heading, the search matched the same title in the references, and the whole book landed in one section, so chapters got 0 cards without an error                                                                    |
| 63  | Text keeps its size; the spacing unit behind padding, gaps and control heights shrinks with the viewport's height, to three quarters on a short screen. Long card text steps down a size or two, multiple choice a step sooner; its result is one line beside Continue, which sits above the source on wide screens. Review fits a 14-inch 1920×1080 laptop at Windows' default 150% scaling (a 1280×590 viewport) (supersedes keeping the larger base size from the Phase 1 session) | On the tester's 16:9 laptop the interface felt zoomed in, though the text was fine; buttons under long cards were cut off by up to 360px. Scaling everything with the screen also fit, but changed the side margins, which were fine |
| 64  | Ask opens with no explanation; the field's placeholder names the course                                                                                                                                                                                                                                                                                                                                                                                                               | A tester found the intro wordy and said no explanation would be better                                                                                                                                                               |
| 65  | A citation in Ask opens its passage as text, with the quoted words marked, the book, section and page, and a link to the PDF at that page; the page image isn't shown in Ask                                                                                                                                                                                                                                                                                                          | The page image made the answer harder to follow on a laptop and was illegible on a phone                                                                                                                                             |
| 66  | The chapter picker leads with chapters already covered, offers a from–to range, and keeps the full list one step away                                                                                                                                                                                                                                                                                                                                                                 | A 47-chapter textbook made picking a test's few chapters a long scan; tests cover what has been taught                                                                                                                               |
| 67  | On phones the top bar is the Engram name and a menu button that opens a sidebar with every page and Sign out; wider screens keep the top bar (refines D50)                                                                                                                                                                                                                                                                                                                            | The top bar wrapped to two or three rows on a phone, and a menu is what people expect on a mobile site                                                                                                                               |
| 68  | On phones the four ratings are one compact row pinned to the bottom, and the source follows the card directly; on wide screens the source sits beside the card                                                                                                                                                                                                                                                                                                                        | The source sat below the ratings, so reading it meant losing sight of the card                                                                                                                                                       |
| 69  | On phones the calendar shows one week at a time, as a list of days with what's due on each; the month grid stays on wider screens                                                                                                                                                                                                                                                                                                                                                     | A month grid was too much for a phone: spread out, taller than its contents and scrolling sideways on its own                                                                                                                        |
| 70  | Ask's send button is an icon inside the question field (Enter still sends), the field grows with the question, and Clear sits above the conversation as "New question"                                                                                                                                                                                                                                                                                                                | The Ask and Clear buttons squeezed the field until its placeholder was cut off                                                                                                                                                       |
| 71  | A job that fails for good marks its material or chapter failed, in the database; a job abandoned on its last attempt is failed instead of reclaimed                                                                                                                                                                                                                                                                                                                                   | A book that crashed its worker every time stayed "Reading" forever, and an attempt that would be retried briefly showed as a failure                                                                                                 |
| 72  | A material that can't be read records why (no text, protected, damaged, stalled, unknown) and the course page says what to do; a scanned textbook, a password or a damaged file is spotted before Docling runs and fails at once                                                                                                                                                                                                                                                      | One message for every failure told students to try a PDF even when the file was one, and a scanned textbook showed as ready with no chapters                                                                                         |
| 73  | A failed chapter is retried with one Try again button (a narrow database function queues it again), and a material being read shows its step (waiting, reading, figures, almost ready)                                                                                                                                                                                                                                                                                                | Unmarking and marking a chapter again was a workaround, not a control; and one "Reading it now" line for a wait of several minutes gave no sign anything was happening                                                               |
| 74  | A failed card batch is sent once more before the chapter goes on without it; a chapter left with no cards fails (and is retried as a job) instead of showing ready; an ended session sends every page to sign-in with "You were signed out"                                                                                                                                                                                                                                           | A batch lost to one bad response silently thinned a chapter's cards, "Ready · 0 cards" hid a failure, and each page failed differently when the session ended                                                                        |
| 75  | A dark theme redefines the role tokens under `html[data-theme="dark"]`; a sun and moon button in the bottom-left corner (in the menu on phones, absent from review) switches it, kept per browser in localStorage and applied before the page paints                                                                                                                                                                                                                                  | Every color was already a role token, so dark mode cost one block of values rather than a redesign; a per-browser setting needs no migration, and suits a preference that belongs to the screen as much as the person                |
| 76  | Findings from the Phase 2 exit session and the first weeks of daily use are collected for a Phase 4 UI/UX pass after about two weeks of regular use, not fixed one at a time; anything that stops users studying is fixed at once. The showcase phase becomes Phase 5                                                                                                                                                                                                                 | Nothing blocked daily study after the session, and real use will show more than a single session; batching avoids redesigning a screen twice                                                                                         |
| 77  | Session goals are dropped. A subject lock shows only one course's cards for the day instead; every course's cards are shown by default                                                                                                                                                                                                                                                                                                                                                | How session goals would work was never clear, and exam focus mode covers studying for a test; studying one subject for a day is a concrete need                                                                                      |
| 78  | An optional settings page may be added in Phase 3; its contents are decided when it's built, and every setting has a default that works (refines UX principle 3)                                                                                                                                                                                                                                                                                                                      | More people want to use Engram, and their preferences will differ more; no one has to visit the page, so it keeps zero required configuration                                                                                        |
| 79  | Before new Phase 3 features: alerts on failed jobs and API errors, an alert on inference spend, confirmed database backups, and each user's logging consent confirmed before the review-order experiment                                                                                                                                                                                                                                                                              | Daily use has started, so a failure nobody notices is the largest risk, and the experiment measures nothing without logged ratings                                                                                                   |
| 80  | The eval suites come first in Phase 3, on an OpenStax corpus that later seeds the demo account                                                                                                                                                                                                                                                                                                                                                                                        | They decide when card generation can move to a cheaper model and whether short-answer grading can be trusted; one corpus serves both evals and the demo                                                                              |
| 81  | Flagged cards get a list where a flag can be undone or the card removed (carries out D3's triage view)                                                                                                                                                                                                                                                                                                                                                                                | A flag suspends a card for good, so a mistaken tap loses the card with no way back                                                                                                                                                   |
| 82  | Anki export moves to Phase 5                                                                                                                                                                                                                                                                                                                                                                                                                                                          | It guards against lock-in rather than helping anyone study now                                                                                                                                                                       |
| 83  | Aggregate usage statistics are published only once enough users have agreed to logging that no one can be picked out; until then only eval and benchmark results are published                                                                                                                                                                                                                                                                                                        | With one to three users, an aggregate is one person's data                                                                                                                                                                           |
| 84  | The learner model is fitted on a public spaced-repetition review dataset and checked against users' reviews                                                                                                                                                                                                                                                                                                                                                                           | A few users won't produce enough reviews to fit a model on their own                                                                                                                                                                 |
| 85  | No moderated session closes Phase 4; from then on users report what they dislike themselves                                                                                                                                                                                                                                                                                                                                                                                           | By then Engram should work as a released app, without the developer sitting beside the user                                                                                                                                          |
| 86  | A Send feedback link lets users report a problem from inside the app; admins read the reports in the app                                                                                                                                                                                                                                                                                                                                                                              | Users are to report what they dislike themselves (D85), and the card flag is the only report there is; non-technical users won't open a GitHub issue                                                                                 |
